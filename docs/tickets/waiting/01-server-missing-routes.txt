## Context

The Node.js server (server/src/) already has models + routes for:
  users, registrations, tournaments, martial-arts, organizations,
  rank-systems, role-definitions

The app's database.web.ts also needs endpoints for five more collections
that currently have NO server equivalent. All five must be created.
Additionally, several existing routes return full collections with no
filtering, but the app queries by a related field (e.g., userId). Those
routes need to gain optional query-param filters.

## Execution Plan

### A. Shared helper — normalize _id → id

In server/src/utils/normalize.ts (new file):

  export function normalizeId(doc: any): any {
    if (!doc) return doc;
    const { _id, __v, ...rest } = doc;
    return { id: String(_id), ...rest };
  }

  export function normalizeIds(docs: any[]): any[] {
    return docs.map(normalizeId);
  }

Apply normalizeId/normalizeIds in every route's responses (both new and
existing). Each router.get('/'), router.get('/:id'), router.post('/'),
router.patch('/:id') should wrap its lean() result through normalizeId.

### C. New Route Files

#### server/src/routes/coachAssignments.ts
  GET    /api/coach-assignments            → list all (supports ?coachId=, ?athleteId=)
  GET    /api/coach-assignments/:id        → get one
  POST   /api/coach-assignments            → create { coachId, athleteId }
                                             Return 409 if duplicate
  DELETE /api/coach-assignments/:id        → delete

#### server/src/routes/tournamentTemplates.ts
  GET    /api/tournament-templates         → list all
  GET    /api/tournament-templates/:id     → get one
  POST   /api/tournament-templates         → create
  PATCH  /api/tournament-templates/:id     → update
  DELETE /api/tournament-templates/:id     → delete

#### server/src/routes/userMartialArtRanks.ts
  GET    /api/user-martial-art-ranks       → list all (supports ?userId=, ?martialArtId=)
  GET    /api/user-martial-art-ranks/:id   → get one
  POST   /api/user-martial-art-ranks       → upsert (findOneAndUpdate with upsert:true)
                                             Body: { userId, martialArtId, rankSystemId }
  DELETE /api/user-martial-art-ranks/:id   → delete

#### server/src/routes/bracketSeeds.ts
  GET    /api/bracket-seeds/:tournamentId  → get seeds for tournament (returns {} if none)
  PUT    /api/bracket-seeds/:tournamentId  → upsert seeds for tournament
                                             Body: { seeds: Record<string, string[]> }

#### server/src/routes/weighInResults.ts
  GET    /api/weigh-in-results             → list all (supports ?tournamentId=, ?registrationId=)
  GET    /api/weigh-in-results/:id         → get one
  POST   /api/weigh-in-results            → create
  PATCH  /api/weigh-in-results/:id         → update

### D. Update Existing Routes to Support Query Filtering

These routes currently return all records. Add optional query-param
filtering so the client can fetch only what it needs:

server/src/routes/registrations.ts — GET /
  Add: if (req.query.userId) filter.userId = req.query.userId
  Add: if (req.query.tournamentId) filter.tournamentId = req.query.tournamentId

server/src/routes/rankSystems.ts — GET /
  Add: if (req.query.martialArtId) filter.martialArtId = req.query.martialArtId

server/src/app.ts — GET /api/users (already protected by requireAuth)
  Add: if (req.query.email) filter.email = (req.query.email as string).toLowerCase()
  Add: if (req.query.role) filter.role = req.query.role
  (This lets the app fetch athletes via ?role=athlete and look up by email)

## Comments
- BracketSeeds uses PUT (not POST) because it's a pure upsert by tournamentId.
- UserMartialArtRanks POST is also an upsert — use findOneAndUpdate with
  { upsert: true, new: true } on { userId, martialArtId } filter.
- seeds field on BracketSeed: Mongoose Map type serializes to a plain
  object in .lean() — verify this in tests, may need JSON.stringify/parse.
- All new routes should be unprotected (no requireAuth) for now, consistent
  with most existing routes. Add auth later if needed.
- TypeScript: add proper req.query types or cast with (req.query.x as string).
