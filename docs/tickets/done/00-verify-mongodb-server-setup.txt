## Context

The server (server/src/server.ts) already calls connectDB(MONGO_URI) and
seedAdmin() on startup. Mongoose models are defined. The code is correct —
what needs to be verified is the environment setup on the developer's
Windows machine and that end-to-end data persistence actually works.

server/.env.example contains the right defaults but the actual server/.env
file must be created before the server will pick up the config.

## Execution Plan

### A. Install & start MongoDB on Windows

1. Download MongoDB Community Server from mongodb.com/try/download/community
   Choose: Windows, .msi installer, the latest stable release.

2. During install, choose "Install MongoD as a Service" — this makes
   MongoDB start automatically with Windows and run in the background.
   Default data directory: C:\Program Files\MongoDB\Server\<version>\data\

3. After install, verify MongoDB is running:
     Open PowerShell (or cmd) and run:
       mongosh
     You should see a > prompt. Type:
       db.runCommand({ ping: 1 })
     Expected output: { ok: 1 }
     Type 'exit' to leave.

   If mongosh is not found, install MongoDB Shell separately from:
     mongodb.com/try/download/shell

4. If the service is not running, start it manually:
     net start MongoDB
   Or via Services (Win+R → services.msc → find MongoDB → Start).

### B. Create server/.env

Copy server/.env.example to server/.env:
  (In terminal from the project root)
  cp server/.env.example server/.env

The defaults in .env.example are correct for a local dev machine:
  PORT=3001
  MONGO_URI=mongodb://localhost:27017/kumite
  JWT_SECRET=change_me_in_production
  ADMIN_EMAIL=admin@kumite.app
  ADMIN_PASSWORD=Admin@1234

The 'kumite' database will be created automatically by MongoDB the first
time a document is inserted — you do not need to create it manually.

Make sure server/.env is in .gitignore. Add it if not already there:
  echo "server/.env" >> .gitignore

### F. Verify data persistence end-to-end

This is the key test: write data, restart the server, read it back.

Step 1 — Register a test user (server must be running):
  curl -X POST http://localhost:3001/api/auth/register \
    -H "Content-Type: application/json" \
    -d "{\"email\":\"test@kumite.app\",\"password\":\"Test@1234\",\"fullName\":\"Test User\",\"role\":\"athlete\"}"

Expected: 201 response with { token: "...", user: { id: "...", email: "test@kumite.app", ... } }
Save the returned token — you will need it for protected routes.

Step 2 — Stop the server (Ctrl+C in the terminal running npm run dev)

Step 3 — Restart the server:
  npm run dev

Step 4 — Login with the same credentials:
  curl -X POST http://localhost:3001/api/auth/login \
    -H "Content-Type: application/json" \
    -d "{\"email\":\"test@kumite.app\",\"password\":\"Test@1234\"}"

Expected: 200 response with a new { token, user }
If you get 401 "Invalid credentials", data was not persisted (check MONGO_URI).

Step 5 — Verify via MongoDB Shell (optional but definitive):
  mongosh
  use kumite
  db.users.find({}, { passwordHash: 0 })
  // Should show both admin@kumite.app and test@kumite.app

## Common Failure Modes on Windows

ECONNREFUSED / MongoNetworkError
  → MongoDB service is not running. Run: net start MongoDB

Authentication failed
  → MongoDB was installed with auth enabled. Either disable auth for dev
    (edit mongod.cfg: security.authorization = disabled) or add credentials
    to MONGO_URI: mongodb://username:password@localhost:27017/kumite

Port 3001 already in use
  → Another process is on 3001. Change PORT in server/.env to 3002 and
    update SERVER_BASE_URL in constants/serverConfig.ts to match.

ts-node not found
  → Run 'npm install' inside the server/ directory.

mongosh not recognized
  → Install MongoDB Shell separately or use the full path:
    "C:\Program Files\MongoDB\Server\<version>\bin\mongosh.exe"
